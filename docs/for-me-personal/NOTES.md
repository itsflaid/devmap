# DevMap Reverse-Engineering Notes

## Repo Overview
- Monorepo: pnpm workspaces, `@flaid/devmap` npm package lives in `packages/cli`.
- Landing site in `apps/web` (Astro). Root scripts route via pnpm filters.
- CLI deps: `commander`, `ignore`, `p-limit`, `ts-morph`. Built with `tsx` (dev) + `tsc` (dist). Node >=22.12, ESM.
- CLI bin: `./dist/index.js` (src/index.ts). TypeScript 6, no separate build config beyond tsc.

## CLI entry / commands (src/index.ts, read)
- `commander` program `devmap`. Commands: init, analyze, onboarding(onboard), map, flow, explain, config model, doctor.
- All commands accept `--json`. Wrapped in `runSafely` (utils/errors).
- No-arg → printWelcome; --help → printHelp.
- Commands dispatch to commands/*.ts handlers.

## Pipeline orchestrator (src/analyzers/pipeline/projectMap.ts, read — 1140 lines)
- `createProjectMap(projectRoot, callAI?)` is the core orchestration:
  1. `scanFiles(projectRoot)` → ScannedFile[]
  2. `analyzeFiles(files)` → Record<path, FileAnalysis> (via analyzerRegistry)
  3. `buildDependencyGraph(files, analyses)` → fileGraph Record<path, deps[]>
  4. `countReferences(graph)`
  5. `detectFramework(detectFrameworks)` + `detectProjectMetadata`
  6. `detectEntryPoints(graph)`
  7. `detectRoutes(files, frameworks, graph)`
  8. `detectDatabase(files)`
  9. `extractEntities(files, routes)` → EntityGraph (Step 1)
  10. `detectCapabilities(routes, entityGraph)` (Step 2)
  11. `detectFeatures(...)` + attachFeatureEntryPoints (Step 3)
  12. Optional AI: `inferDomain(input, callAI)` → DomainInferenceResult, then `mergeDomainFeatures` (Step 4/5)
  13. `rankCriticalFiles`
  14. Build `fileIndex` via createFileIndexEntry
  15. `generateMinimalFlows` → feature flows + request flows
- Returns `ProjectMap` (SNAPSHOT_SCHEMA_VERSION = "1").
- **Important**: AI is injected via `callAI` param (decoupled). Domain inference is OPTIONAL — if no callAI or it fails, static features still complete.
- AI vs deterministic: domain inference is the only AI step in map creation. Everything else deterministic.
- `ProjectMap` fields: version, generatedAt, agentInstructions, fingerprint, projectRoot, framework, project(ProjectMetadata), stats, entryPoints, criticalFiles, routes, apiRoutes, externalServices, database?, features, entityGraph?, capabilities?, domain?, flows, onboarding, changeImpact, warnings?, dependencies(package.json), fileGraph(imports), ai?, fileIndex.
- `fileIndex`: per-file metadata (analyzer, analysisConfidence, hash, imports, exportedSymbols, symbols, topFunctions, lines, purpose?, scope, featureRefs, searchTerms, importance).
- FileScope: api|ui|database|config|service|cli|test|docs|unknown.
- FlowInfo: name, purpose, type(architecture|feature|request|data|dependency), entryPoint?, steps[{label,file?,purpose?}], mermaid?, confidence.
- Critical files ranked by score = referencedBy*3 + entrypoint(12) + execution bonus(16) + core concern(3) + semantic bonus + framework convention(2); types/constants penalized -8.
- `FileIndexEntry` scope via regex-based `classifyFileScope`.
- Features attach entry points; Authentication has special ordering/handling.
- flows: generateFeatureFlows (high-confidence, limit 3) + generateRequestFlows (api routes, limit 5).
- `createProjectFingerprint`: hash of path:contentHash sorted lines.

## Analysis layer (src/analyzers/analysis/, read)
- `fileScanner.ts`: `scanFiles` — recursive dir walk with p-limit(50) concurrency, sorts by path. Reads whole file into memory. `ScannedFile {path, absolutePath, extension, size, lines, content}`.
- `fileAnalysis.ts`: types only — `FileAnalysis {analyzer, confidence(high/medium/low), imports, exports, symbols[], topFunctions[], routes?}`, `SymbolInfo {name,kind,line,exported,async?}`, `FileAnalyzer` interface.
- `analyzerRegistry.ts` (pipeline/): `AnalyzerRegistry.analyze` — first analyzer whose `supports()` returns true wins; on throw, falls through to next. `analyzeFiles` runs ALL files in Promise.all, order: TsMorphAnalyzer → HeuristicAnalyzer → FallbackAnalyzer. Throws "No analyzer supports" if none.
- `tsMorphAnalyzer.ts`: uses ts-morph in-memory project (useInMemoryFileSystem, skip tsconfig, allowJs, ES2022). Native .ts/.tsx/.js/.jsx. Preprocessors for .vue/.svelte/.astro (extract script block, virtual path with proper ext). Extracts imports (import/export-from/require), exports (getExportedDeclarations keys), symbols (function/class+methods/interface/type/enum/const arrow). topFunctions: filter kind + sort exported-first then line, slice(0,8). Confidence "high". Removes source file from project after (per-file createSourceFile).
- `heuristicAnalyzer.ts`: regex-based for .cjs/.cts/.mjs/.mts/.cs/.go/.java/.php/.py/.rb. Confidence "medium". Regex import/symbol detection (scope-unaware, not comment-aware — noted TODO for tree-sitter). FallbackAnalyzer supports everything, returns empty, confidence "low".
- `filterEngine.ts` (file scanning ignore): IGNORED_DIRECTORIES (big set incl .git, .devmap, dist, node_modules...), IGNORED_EXTENSIONS, IGNORED_FILES (lockfiles). Loads .gitignore + .git/info/exclude via `ignore` pkg, cached per projectRoot in module-level Map. Also ignores .env, public/assets, .min.js/.ts.

## Graph layer (src/analyzers/graph/, read)
- `dependencyGraph.ts`: `buildDependencyGraph(files, analyses)` → FileGraph = Record<path, string[]>. Only local imports (specifier starts with ".") resolved. Non-relative imports skipped. `resolveImport` tries extension candidates + index files + .js→.ts swap. `countReferences` = in-degree. IMPORT_RE regex fallback if no analysis.
- `dependencyMap.ts`: `buildReverseGraph` (invert). `MapTreeNode {path, children, isCycle, truncatedCount?}`. `buildBoundedTree(graph, root, maxDepth, {ancestors, filter, maxChildren})` — DFS, per-branch visited (ancestor) set for cycles, caps children at DEFAULT_MAX_CHILDREN=25. `collectNodesWithinDepth` — BFS dedup within maxDepth.
- `entryPoints.ts`: `detectEntryPoints` — files matching page/layout/middleware/server/app/index/main/route patterns OR (not imported && has deps). Scored by pattern, sliced to 20.
- `sourceScope.ts`: `isArchitectureSource` — false if path has non-prod segment (__fixtures__, test, docs, demo, examples, fixtures, samples, coverage) or ends .test/.spec.
- Graph is IN-MEMORY ONLY, built fresh each createProjectMap call. File-level, import edges only. No node/edge types beyond file→file.

## Detectors layer (src/analyzers/detectors/, read — all done)
- `serviceDetector.ts`: `detectExternalServices(files)` → sorted string[] of external service names. Sources: (1) package.json deps + devDeps, (2) regex-scan imports across .ts/.tsx/.js/.jsx, (3) content-includes SOURCE_SERVICE_SIGNALS. Matched against SERVICES registry (needles→name). `isServiceSignalDefinitionFile` excludes registry/ + serviceDetector/featureDetector files themselves from false positives.
- `capabilityDetector.ts`: `detectCapabilities(routes, entityGraph)` → CapabilityInfo[] {kind: crud|sharing|collaboration|discovery|publishing|social|file-management|real-time|search|reporting, name, entities[], evidence[], confidence}. CRUD detection: group API routes by resource segment (first non-dynamic, non-api/vN segment, filtered by NON_RESOURCE_SEGMENTS), require GET(read)+POST/PUT/PATCH(write) + optional DELETE → "X Management", full=high else medium. Behavioral: BEHAVIORAL_SIGNALS table (path regex per kind, highConfidenceAt threshold, minimumMatches). Only API routes (page routes removed to kill false positives — comment documents old bug). Confidence high iff match count >= highConfidenceAt. Entity names resolved via entityGraph.entityNames, singularize fallback. Dedup by kind, merge entities/evidence, take higher confidence.
- `frontendFeatureDetector.ts`: `detectFrontendPageFeatures(routes, fileGraph)` — group page routes by top path segment (skip /[dynamic], NON_FEATURE_PAGE_SEGMENTS={auth,oauth,callback,api,static,assets,public}), singularize → feature name, medium confidence. Runs UNCONDITIONALLY alongside entity features (comment: entity fallback chain stops at first non-empty source, so page-only features like "Quran" never surfaced when a single Prisma model exists). `detectClientRouteFeatures(files, fileGraph)` — for SPAs: regex-parse React Router (JSX + object/data-router), Vue Router (identifier + lazy import), svelte-spa-router (gated on its import). Resolves component id → file via graph imports (stem match), lazy specifier via path normalization. `collectOwnedFiles` — BFS reachable from seeds; file is "owned" iff every referrer is also in reachable set (shared files excluded — false-negative over false-positive bias). Uses singularize from fallbackExtractor.
- `index.ts`: re-exports all detectors (framework, routes, externalServices, database, capabilities, frontend page/client features).

## Features layer (src/analyzers/features/, read — all done)
- `featureDetector.ts` (805 lines): `detectFeatures(files, analyses, routes, database?, entityGraph?, capabilities?, fileGraph?)` → FeatureInfo[]. FeatureInfo {name, purpose, files, entryPoint?, entryPoints, businessFlow, searchTerms, confidence, evidence}. Four feature sources merged via similarity engine:
  1. ROLE_FEATURES: documentation/landing-ui/cli-command roles → "Documentation"/"Web Landing"/"CLI Commands". Documentation strictly filtered (isDocumentationEvidence excludes .github/ meta).
  2. FEATURE_SIGNALS: registry-driven vocabulary detection (path/import matching). `matchesSignal` — importOnly (AI Integration) uses isAiProviderImport + hasAiProviderUrl + ai-integration role; others path-term match then import match. `matchesPathTerm` word-boundary for ≤7 chars, substring for ≥8. Pre-filters technical files + excludes registry files (self-match prevention). minimumDistinctFiles gate.
  3. capabilitiesToFeatures: caps → features, drops non-high-confidence caps with no resolvable entry points (weak route-only detection).
  4. entityGraphToFeatures: entity ownership model — TRUE CHILD (single one-to-many parent AND no own children or child-like suffix) skipped; STANDALONE (multiple parents OR owns others) gets feature "X Management". INFRASTRUCTURE_ENTITY_NAMES excluded (NextAuth/Lucia internals, audit tables). Relations deduped. Purpose built from owned (one-to-many) + peers (many-to-many). Confidence: prisma source=high, single reference-tier file=low, else medium.
  - `classifyFileTier(path)`: primary/supporting/reference/excluded (migrations/.sql/generated excluded, schema.prisma & config = reference, api/routes/service/usecase/route/handler/hooks/stores = primary).
  - `scoreEntryPointRelevance`: lower=better; utils/helpers/constants/types=100 (excluded), route/handler=5, api=10, service/usecase/action=20, services=25, pages/app page/layout=30, components=50, lib=60, else 70. ENTRY_POINT_EXCLUDE_THRESHOLD=90.
  - `calculateFeatureConfidence`: ≥2 high-quality=high, ≥1 high or ≥2 files=medium, else low.
  - `detectAuthenticationSemanticRole(path, symbols, imports, content)` → auth-config|guard|provider|consumer|null. Regex on path+symbols+imports+content. auth-config (auth.ts, nextauth/getserversession), guard (proxy/middleware + auth+guard), provider, consumer. `enrichAuthenticationFeature` enriches/creates "Authentication" feature. `orderAuthenticationFiles`/`authenticationFilePriority` ordering. Fallback extractImports/extractSymbols regex when no analysis.
- `featureMerge.ts`: Centralized merge replacing two old buggy sites (both used name equality — "Plan Management" vs "Customizable Plans" never merged). `mergeIntoFeatureList(features, addition, threshold)` — findSimilarFeature via similarity engine; no match → push new; match → enrich existing (canonical first-seen name wins). `mergeFeatureData`: name existing wins, purpose existing unless generic, files/evidence/entryPoints union dedup, searchTerms union capped MAX_SEARCH_TERMS=8, confidence higher, businessFlow existing if meaningful. `mergeDomainFeatures` for AI features. `toFeatureIdentity` derives relatedEntities from name pattern "X Management/System/Module" + Title-Case searchTerms.
- `featureSimilarity.ts`: Reusable similarity engine. FeatureIdentity {name, files, searchTerms, relatedEntities, purpose?}. Weighted scoring: fileOverlap 0.45, termOverlap 0.25, entityOverlap 0.20, nameSimilarity 0.10. Threshold 0.35. jaccardSimilarity (empty∩empty=1, one empty=0), trigramSimilarity (Dice coefficient on char trigrams, padded). `computeSimilarity`, `isSimilarFeature`, `findSimilarFeature`, `computeSimilarityWithExplanation` (@internal, per-factor breakdown + weaknesses for future doctor output). Fingerprint foundation (unused): buildFeatureFingerprint (sorted |joined signatures), fingerprintSimilarity (renormalized weights sans nameSimilarity). normTerms lowercase/trim no stopword strip.
- `index.ts`: re-exports detectFeatures, auth roles/order, classifyFileTier, merge utils, similarity engine.

## Inference layer (src/analyzers/inference/, read — all done)
- `domainInference.ts`: `inferDomain(input, callAI, projectRoot?)` → DomainInferenceResult | null. This is THE AI step in map creation. DomainInferenceInput is structured metadata ONLY (entityNames, relations, capabilities kinds, technicalFeatures names, routeCount, framework, ownershipPattern, crossUserFields, absentCapabilities) — intentionally no raw source code (~300-500 tokens/call). Response parsed as strict JSON (markdown fences stripped), validated (domain+summary required), domainFeatures filtered/sliced 6, confidence clamped 0-1 default 0.7. **Cache**: .devmap/domain-cache.json keyed by sha256 hash (v2 versioned) of sorted input — makes analyze idempotent. Hash change → miss → LLM call. Cache read/write failures non-fatal. Skip if no entities AND no capabilities. Any callAI throw → null (enhancement, not blocker). `domainFeaturesToFeatureInfo`: AI features → FeatureInfo with confidence MEDIUM (never high), searchTerms from relatedEntities+name words (so similarity engine can merge with static). `buildDomainInferenceInput`: detects absent capabilities, computes ownership pattern, slices: entities 15, relations 10, technicalFeatures 10 (high+medium only), crossUserFields 5, absentCapabilities 8.
- `ownershipTopology.ts`: `classifyOwnershipTopology(entityGraph, relations)` → {pattern, crossUserFields, evidence}. Patterns: single_user_isolated | shared_access | direct_messaging | unclear. Heuristics: CROSS_USER_FIELD_NAMES (participants/members/invitedBy/sharedWith/senderId/recipientId...), many-to-many with User, ≥2 FK to User (multi-fk evidence), sender/recipient FK → direct_messaging. Evidence strings recorded for prompt. Purpose: disambiguate domain ("Message" could be chat/log/note) — single_user_isolated → personal tool, not chat.
- `index.ts`: re-exports inferDomain/domainFeaturesToFeatureInfo/buildDomainInferenceInput + classifyOwnershipTopology.

### AI summary (separation of AI vs deterministic)
- AI has exactly 3 call sites: (1) domain inference during map creation (domainInference.ts), (2) snapshot enrichment file purposes + feature terms (snapshotEnrichment.ts, invoked separately), (3) Q&A text generation at runtime: analyze command (buildAnalyzeMessages), flow narration (buildFlowNarrationMessages), explain command (buildExplainMessages). All AI output feeds metadata/context; core structure (files, graph, routes, features, flows, critical files) is 100% deterministic.
- All AI errors are non-fatal (return [] or null), cached for idempotency (domain only), and structured (JSON) with temp 0 for enrichment and domain inference, temp 0.2 for chat.
